# Optimal Tree Converting

## 디지털 회로도

```sh
python utiles/graph2dot.py input/toy.json --svg
```

JSON의 DAG에서 일반 프리뷰용 DOT과, 직접 배치·배선한 독립적인 SVG 회로도를 생성한다. 기본 DOT는 외부 이미지나 고정 좌표 없이 종류/이름이 적힌 박스로 표시하므로 VS Code DOT 프리뷰에서 바로 볼 수 있다. 정밀한 게이트 기호, 핀 접점과 교차 점프는 `--svg` 결과에서 확인한다.
기본 입력은 `input/adder.json`이며 결과는 입력 옆에 `.dot`, `--svg`를 지정하면 `.svg`로 저장한다.
SVG 생성에는 Graphviz, Node.js, 외부 Python 패키지가 필요하지 않는다.

`input/library.json`의 모든 셀 이름을 노드 `op`에 사용할 수 있다.
`op: "CELL"`과 `cell: "AOI21_X1"` 형식도 지원하며 입력 포트 번호는 라이브러리 `inputs` 순서에 대응한다.
AND, NAND, OR, NOR, XOR, XNOR, INV, BUF 계열은 SVG 논리 기호로 표시하고, AOI, OAI, MUX 등의 다른 셀은 셀 이름만 적힌 박스로 표시한다.
INPUT/OUTPUT은 포트 이름, CONST는 0 또는 1을 표시한다. 모든 출력 포트는 오른쪽 끝 열에 모으고 JSON `outputs` 배열 순서대로 위에서 아래로 배치한다. 출력 박스 폭은 가장 긴 출력 이름에 맞춰 통일하여 양쪽 경계를 정렬한다. `outputs`가 없으면 노드 배열의 출력 순서를 사용한다.
기초 게이트의 인스턴스 이름은 기호에 표시하지 않는다.

모든 와이어는 수평·수직 선분으로 배선한다. 기호와 박스에는 별도의 핀 돌출선을 그리지 않으며, 와이어 끝점은 기호 경계와 일치한다.
공유 출력의 분기점에는 접속 점을 표시한다. SVG에서 서로 다른 신호의 교차에는 작은 점프 표시를 넣으며, 같은 신호의 분기에는 점프를 넣지 않는다. 점 없는 선 교차는 전기적 접속을 뜻하지 않는다.
긴 연결에는 중간 배선 슬롯을 배정하여 다른 셀을 통과하지 않도록 한다. 배선 후 일직선 구간을 합치고, 다른 셀 또는 다른 신호의 배선과 겹치지 않는 경우 불필요한 계단식 경로를 더 짧은 경로로 바꾼다.

`--fast`는 배치 정렬 횟수만 줄이며 직각 배선을 유지한다.
`--basic`은 모든 게이트를 이름/종류가 적힌 박스로 표시한다.
`-o`로 DOT 출력 경로를 지정할 수 있다.

기본 DOT는 Graphviz `dot` 엔진과 직각 배선을 사용한다.
예전 고정 좌표 DOT가 필요하면 `--fixed-dot`을 지정하고 `neato -n2`로 렌더링한다.
이 형식은 일반 DOT 프리뷰용이 아니며 로컬 SVG 이미지 로딩 지원도 필요하다.

```sh
python utiles/graph2dot.py input/toy.json --svg
python utiles/graph2dot.py input/toy.json --fixed-dot -o input/toy-fixed.dot
neato -n2 -Tsvg input/toy-fixed.dot -o input/toy-graphviz.svg
```

고정 좌표 DOT의 기초 게이트 이미지는 `utiles/symbols/schematic/`에 생성한다.
SVG 회로도는 모든 기호를 내장하여 이 디렉터리 없이도 열 수 있다.

### Python에서 함수로 사용

저장소 루트에서 다른 Python 코드에 import하여 사용할 수 있다.

```python
from utiles.graph2dot import render_schematic, export_schematic

# JSON 경로 또는 이미 읽은 graph 딕셔너리를 받는다. 파일을 쓰지 않는다.
rendered = render_schematic("input/toy.json")
dot_text = rendered["dot"]
svg_text = rendered["svg"]

# 파일로 저장하고 생성 경로와 노드/연결 수를 반환한다.
result = export_schematic("input/toy.json", "input/toy.dot", with_svg=True)
print(result["dot_path"], result["svg_path"])
```

두 함수 모두 `fast`, `basic`, `fixed_dot` 키워드 옵션을 지원한다.
`export_schematic`은 기본적으로 SVG도 저장하며 `with_svg=False`로 DOT만 저장할 수 있다.
JSON 경로를 넘기면 출력 경로를 생략할 수 있고 입력 옆에 저장한다. 그래프 딕셔너리를 넘길 때는 출력 경로를 지정한다.
상대 경로는 호출하는 코드의 현재 작업 폴더를 기준으로 해석한다.
import와 `render_schematic`은 파일을 생성하거나 메시지를 출력하지 않으며, 오류는 예외로 전달한다.
기존 CLI 명령은 동일하게 사용할 수 있다.

논리 회로를 셀 라이브러리로 매핑할 때 면적, 대표 누설전력, 지연의 가중치 합을 최소화하는 초기 비용 모델을 사용한다.
현재 `s1_ahoCorasick.py`, `s2_main.py`의 매핑 알고리즘은 미구현이다. 이 문서는 `utiles/lib2json.py`의 데이터 필터링 및 상수 추출 기준을 정의한다.

## 라이브러리 변환

```sh
python utiles/lib2json.py
```

기본 입력은 `reference/library/NangateOpenCellLibrary_typical.lib`, 출력은 `input/library.json`이다.
다른 경로는 `python utiles/lib2json.py <input.lib> -o <output.json>`으로 지정한다.
변환기는 입력 원본을 수정하지 않는다. 원본의 별도 보관은 사용자가 관리한다.

JSON 최상위 키는 셀 이름이다. `cells` 계층과 라이브러리 메타데이터는 저장하지 않는다.
`attributes` 계층은 제거한다. `area`, `leakage_power`, `delay`는 각각 `{"value": 수치, "unit": 단위}`로 저장한다.
입출력과 논리식의 기존 `inputs`, `outputs`, `functions` 구조는 유지한다.

```json
{
  "INV_X1": {
    "area": {"value": 0.532, "unit": "um^2"},
    "inputs": ["A"],
    "outputs": ["ZN"],
    "functions": {"ZN": "!A"},
    "leakage_power": {"value": 14.353185, "unit": "nW"},
    "delay": {"value": 0.030787218489851796, "unit": "ns"}
  }
}
```

## 대상 셀과 제거 정보

대상은 입력이 있고 출력이 하나이며 출력 논리식, 면적, 대표 누설전력, 유효한 조합 지연 표를 갖는 일반 조합 논리 셀이다.
순차 셀(`ff`, `latch`, `statetable`), 삼상 셀(`three_state`), 물리 전용 셀, 입력 없는 타이 셀 등은 제외한다.
현재 Nangate 원본 135개 셀 중 88개가 남는다. 이는 원본 전체 셀을 지원한다는 뜻이 아니다.

입출력 핀 이름과 출력 논리식은 매핑의 기능적 정확성을 위해 유지한다.
핀 정전용량, 상세 타이밍 표, 상태별 누설전력, 내부전력 표, 전원 핀, 구동 강도, 기타 속성은 계산 후 JSON에서 제거한다.
지연 계산에 쓰는 정전용량과 표는 변환 중에만 사용한다.

## 세 상수의 정의

상수란 같은 셀 종류의 비용을 회로 내 위치 및 연결 상태와 무관하게 고정한다는 의미다.
현재 원본의 특성화 조건은 typical 공정, 1.1 V, 25 °C이다. 다른 공정·전압·온도로 일반화하지 않는다.
변환기는 시간 `1ns`, 누설전력 `1nW`, 부하 정전용량 `(1, ff)` 단위를 확인하며 다른 단위의 입력은 거부한다.
면적은 라이브러리의 원래 수치를 유지한다. 현재 Nangate 라이브러리의 면적 단위는 `um^2`(μm²)이며 [Nangate AND2_X1 데이터북](https://www.cs.upc.edu/~jpetit/CellRouting/nangate/Front_End/Doc/Databook/Cells/AND2_X1_NangateOpenCellLibrary_typical_typical.html)을 근거로 명시한다.
면적 단위는 Liberty 헤더에서 읽은 값이 아니므로 다른 라이브러리를 사용할 때는 별도로 확인해야 한다.

### 면적 A_c

셀의 `area`를 그대로 사용한다. 이는 셀 자체의 면적이며 배선, 배치 여유 공간, 후속 버퍼 삽입 비용은 포함하지 않는다.

### 전력 P_c

원본 셀의 `cell_leakage_power`를 그대로 사용하고 JSON에는 `leakage_power`로 저장한다. 단위는 nW이다.
라이브러리가 제공하는 대표 누설전력이며 상태별 누설전력의 최댓값이나 입력 상태를 새로 가정한 평균을 계산하지 않는다.

입력 활동도와 동작 주파수가 주어지지 않았으므로 내부전력 및 부하 충·방전 전력은 포함하지 않는다.
따라서 이 모델의 전력 최적화는 **대표 누설전력 최적화**이며 총전력 최적화로 해석하지 않는다.

### 지연 D_c

속도 비용은 작을수록 좋은 지연으로 표현하며 `delay`에 ns 단위로 저장한다.

1. 입력 전이 시간을 `s0 = 0.020 ns = 20 ps`로 고정한다.
2. 입력 핀의 `capacitance`를 산술 평균하여 `Cmean,c`를 계산한다.
3. 기준 출력 부하를 `C0,c = 4 × Cmean,c`로 정한다. 단위는 fF이다.
4. 출력 핀의 조합 타이밍 경로에서 `cell_rise`, `cell_fall` 표를 읽는다. `when` 조건이 있는 경로도 포함한다.
5. `(s0, C0,c)`에서 이중 선형 보간하고, 모든 해당 경로와 상승·하강 지연 중 최댓값을 `D_c`로 저장한다.

20 ps와 부하 비율 4는 초기 실험을 위한 명시적 모델 가정이며 실제 회로에서 측정한 조건이 아니다.
부하 비율을 고정하여 셀마다 비슷한 상대적 구동 부담에서 비교한다. 셀마다 절대 기준 부하는 다르다.
표 전체의 산술 평균은 표 격자 분포에 영향을 받으며, 각 표의 최대 부하는 서로 달라 표 전체 최댓값도 동일 조건 비교가 아니므로 사용하지 않는다.

지원하는 표 축은 `input_net_transition`과 `total_output_net_capacitance`이다.
격자는 증가해야 하고 값 행렬 크기가 축 크기와 일치해야 한다. 기준점이 표 밖이면 외삽이나 경계값 대체 없이 변환을 실패시킨다.
`rise_transition`, `fall_transition`, setup/hold 등 제약 표는 전파 지연에 합산하지 않는다.
여기서 최대 지연은 기준 조건에서의 경로별 최댓값이며 실제 부하·전이 시간·공정 변화까지 포괄하는 상한이 아니다.

## 가중치 합으로 결과 선택

평가식은 `J(M) = w_A × A(M) + w_P × P(M) + w_D × D(M)`이며, 값이 작은 매핑 결과 M을 선택한다.
가중치는 음수가 아니고 적어도 하나는 양수여야 한다. 가중치 수치는 아직 정하지 않았다.
JSON에는 세 원래 비용을 저장하고, 가중치와 합산 점수는 저장하지 않아 가중치를 바꿔 재평가할 수 있게 한다.
계산 시 각 비용의 `value`를 사용하고 `unit`으로 단위를 확인한다.

면적, nW, ns의 수치 척도가 다르므로 가중치는 단위 및 척도 변환까지 반영한다.
동일 가중치가 동일 중요도를 뜻하지 않으며, ns를 ps로 바꾸면 지연 가중치도 함께 조정해야 한다.
정규화 비용을 사용할 경우 기준값을 명시하고 모든 후보 및 비교 실험에 동일하게 적용한다.

회로 수준에서 `A(M)`과 `P(M)`은 실제 셀 인스턴스의 비용 합이다.
`D(M)`은 모든 셀 지연의 합이 아니라 입력 도착 시간을 0으로 둘 때 가장 느린 입력→출력 경로의 지연이다.
노드 도착 시간은 `T(v) = D_c(v) + max(T(u): u는 v의 입력 노드)`, 회로 지연은 `max(T(o): o는 출력)`으로 계산한다.
공유 셀의 면적과 전력은 한 번만 센다. 논리적으로 같은 부분도 복제해 배치했다면 실제 인스턴스 수만큼 센다.

셀마다 최소 가중치 점수를 고르는 탐욕 선택이 회로 전체 점수의 최적성을 보장하지 않는다.
특히 경로 지연의 최대 연산과 DAG 공유를 고려해야 하며, 면적·전력·도착 시간의 대안 상태를 보존할 필요가 있다.
최적성 주장은 정의한 모델과 탐색 범위 안에서 검증한 경우에만 사용한다.

## 추후 비교: 출력 부하에 따른 지연 확장

첫 확장은 면적과 대표 누설전력, 입력 전이 시간 20 ps를 유지하고 지연만 `D_c(Cload)`로 바꾼다.
실제 수신 핀 정전용량 합과 지정한 외부 출력 부하로 `Cload`를 계산하고, 초기에는 배선 정전용량을 0으로 둔다.
팬아웃 개수만으로 부하를 대체하지 않는다. 핀 정전용량과 상세 표는 보관한 원본에서 다시 읽는다.

1. 상수 모델로 선택한 결과 M0를 확장 모델에서 재평가하여 지연 예측 오차를 측정한다.
2. 같은 기능, 후보 셀, 가중치, 단위 및 정규화 기준으로 확장 모델에서 선택한 결과 M1과 비교한다.
3. 확장 모델에서 `J(M0) > J(M1)`이면 부하를 생략한 상수화 때문에 더 나쁜 구현을 선택한 사례로 기록한다.

참고로 현재 원본에서 `INV_X1`/`INV_X2`의 기준 지연은 각각 약 30.787/30.251 ps이다.
입력 전이 시간 20 ps와 공통 부하 20 fF로 재평가하면 약 62.477/38.697 ps이다.
이 차이는 구동 능력과 부하의 상호작용을 보여주지만, 특정 가중치에서 결과 순위가 역전되는지는 실제로 평가해야 한다.
확장 모델 또한 배선과 입력 전이 시간 전파를 생략하므로 최종 물리 구현 수치로 해석하지 않는다.

원본에는 셀 상세 표뿐 아니라 단위, 표 템플릿의 축 정의, 동작 조건도 함께 보관해야 재평가할 수 있다.
